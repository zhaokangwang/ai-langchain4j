# 第三阶段：身份、授权技能与业务路由页面

重新编译、重启后端后访问 http://localhost:18080/ ，Ctrl+F5 刷新本地脚本。保留所有原接口，页面依然使用本地 Vue 3，无需 npm 构建或 CDN。

## 身份与技能

页面启动读取 GET /api/demo/capabilities，侧栏显示后端账号和角色。展开顶部“身份与授权技能”可查看数据范围、授权技能的名称/用途/不适用场景及允许工具。买家、客服、仓库分别显示 5、7、2 个技能，欢迎页给出对应业务示例。未授权技能不会混入列表。

身份仍由后端启动参数 `--app.demo.account=buyer`、`service` 或 `warehouse` 指定，切换后需要重启，页面没有提权或角色切换按钮。重启后刷新页面或点击“刷新身份与技能”；同一页面发现账号变化会清空旧会话视图并重新读列表。能力接口失败时显示身份未确认和可重试错误，不编造默认角色或全量授权，业务请求权限仍由后端校验。

## 实时过程与完成记录

实时模式先接收 accepted、authorization 和 routing，再显示实际模型和工具事件：

- 本次身份及允许的数据范围。
- 当前业务判断、筛选原因和候选技能。
- 当前请求的已确认订单或工单；多个候选待选择时展示候选订单。
- 模型实际开始的调用轮次、加载/复用的技能，以及工具执行状态。
- 后端直接拒绝或追问时显示“后端直接回复（未调用模型）”，不显示模型生成步骤。直接拒绝也不会把保留的上一轮业务对象冒充成本次操作对象。

完成后展开回答下方“本轮路由与工具调用”，通过原历史接口读取数据库摘要和实际工具记录；普通 JSON 模式和刷新后的历史消息同样可查看。失败工具显示后端保存的拒绝结果或错误类型，详细参数/结果仍在“查看执行记录”面板。未执行工具不会被推断为“模型直接回答”，以实际模型记录和路由结果区分。

## 尝试与历史兼容

Flyway V4 为 operation_events 增加可空 attempt_no，将 details 扩为 CLOB，保存完整身份和路由快照，不清理旧数据。新 AUTHORIZATION 和 ROUTING 事件记录实际尝试号；SSE 新增 authorization，routing 新增 outcome/state 字段。旧 JSON 响应和旧事件读取继续兼容。

执行记录面板新增“本次尝试的身份与路由”，切换尝试后只读取匹配 attemptNo 的摘要。历史身份来自当时的审计，不用当前页面账号填充。原始操作列表明确标为所有尝试，并标注已知的尝试号。旧事件没有尝试号、内容无法解析，或最近 100 条事件中缺少所选尝试时，提示信息缺失，不根据时间或其他尝试猜测。模型和工具仍按原接口的 selectedAttempt 返回。

## 验证步骤

1. buyer 启动：展开清单确认 5 个技能。问“A1001 的物流在哪”，再问“那它的退款到哪一步了”，查看业务切换及候选技能。
2. buyer 问“查询仓库库存”：应显示后端直接回复、业务范围未授权，模型和工具均无调用。
3. service 启动：刷新后显示 7 个技能。用欢迎页“检查工单材料”测试 AS2001，观察工单号、候选和实际技能加载。
4. warehouse 启动：仅显示仓库两个技能，使用“检查仓库库存”或“分析发货异常”示例。
5. 关闭实时模式后发送问题、刷新历史或切换尝试，展开本轮摘要/执行记录，确认读取已保存事实，不重新调用模型。

上述实际业务问答会使用配置的模型额度。开发验证使用模拟模型和 target/ 下临时 UI 模拟服务器，不接触实际数据库或 DeepSeek；测试页中的“UI 模拟”文字不属于正式业务回答。

前端行为检查：`node --test scripts/frontend-check.cjs`；后端测试覆盖页面资源、授权与路由事件、重试尝试号、SSE、数据库升级及原有权限检查。新增 js/insights.js 负责只读摘要解析和共用展示组件，css/insights.css 负责身份面板和路由卡片排版；所有动态文字使用 Vue 文本插值，不执行审计 JSON 中的 HTML。
